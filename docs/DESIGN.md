# ReLo 디자인 명세

화면을 새로 만들거나 고칠 때 이 문서를 기준으로 삼는다. 값은 모두 `src/web/styles/base.css`의 토큰으로 구현되어 있다. 화면 코드에 숫자를 직접 쓰지 말고 토큰을 쓴다.

스타일 파일: `base.css`(토큰, 기본 글자, 상단 바·하단 탭), `components.css`(버튼·카드·폼·다이얼로그처럼 여러 화면에서 쓰는 조각), `pages.css`(홈·목록·상세·설정의 배치), `dori.css`(도리와 축하 장면).

## 1. 원칙

ReLo는 "해외 직구 클레임을 돈 중심으로 쉽게 신청하고, 단계별로 안심하고 추적하는 개인용 서비스"다. 홈은 **현황판**, 클레임 상세는 **실행판**, 새 클레임은 **단계형 신청**이다.

1. **돈과 사실이 주인공이다.** 사용자가 가장 궁금한 것은 "아직 못 받은 돈"이다. 화면마다 그 정보가 가장 먼저 보이게 한다. 청구액·합의액·실제 회수액·미회수 금액을 항상 나눠서 보여 준다.
2. **한 화면에 주요 행동은 하나.** 주요 버튼(채운 초록 버튼)은 화면당 하나만 둔다. 나머지는 테두리 버튼이나 텍스트 버튼으로 한다. 상태 직접 바꾸기·정정·삭제·복원 같은 드문 행동은 접어 둔 2차 위치(예: 상세의 "사건 관리")에 둔다.
3. **다음 행동을 하나로 알려 준다.** 사용자가 "이제 뭘 하지?"를 고민하지 않게 한다. 클레임마다 다음 할 일 하나와 그 일을 하는 버튼을 보여 준다(`selectNextAction`).
4. **입력보다 판단.** AI와 문서 읽기가 칸을 채우고, 사용자는 확인한다. AI가 채운 칸은 보라색으로 표시하고, 사용자가 고치면 표시가 사라진다. 저장은 항상 사용자가 한다.
5. **조용한 바탕에 기억할 요소 하나.** 그 요소는 도리(펭귄)와 "받아야 할 금액" 숫자다. 나머지는 장식하지 않는다.
6. **모션은 사용자 행동의 결과를 보여 줄 때만 쓴다.** 무언가 열리고, 닫히고, 저장됐다는 것을 알릴 때만 움직인다. 들어올 때마다 미끄러지는 장식 애니메이션은 쓰지 않는다.
7. **누구나 쓸 수 있어야 한다.** 키보드, 스크린리더, 큰 글씨, 모션 줄이기 설정, 375px 휴대폰까지 지원한다.

## 2. 레이아웃과 정렬

### 브레이크포인트

확인 폭은 375 / 768 / 1024 / 1440px이다.

| 이름 | 폭 | 바깥 여백 | 내비게이션 |
|---|---|---|---|
| 모바일 | ≤ 640px | 16px | 하단 탭 바 5칸 (아이콘+글자, 안전 영역 포함) |
| 태블릿 | 641–1023px | 24px | 상단 바 하나에 메뉴 |
| 데스크톱 | ≥ 1024px | 32px | 상단 바 하나에 메뉴 |

- 본문 최대 폭은 1200px이고 가운데에 둔다(`margin-inline: auto`).
- 문단 최대 폭은 70자(`max-width: 70ch`)다.

### 내비게이션

| 화면 | 주소 | 데스크톱·태블릿 | 모바일 하단 탭 |
|---|---|---|---|
| 홈 | `#/` | 상단 바 메뉴 | 1번째 |
| 클레임 | `#/claims`, `#/claims/:id[/:tab]` | 상단 바 메뉴 | 2번째 |
| 새 클레임 | (다이얼로그) | 상단 바 오른쪽 고정 버튼 "새 클레임"(`btn accent`) | 3번째, 가운데 **떠 있는 초록 원 버튼** "새 신청" |
| 휴지통 | `#/trash` | 상단 바 메뉴 | 4번째 |
| 설정 | `#/settings` | 상단 바 메뉴 | 5번째 |

- 상단 바는 화면 위에 붙어 있다(`position: sticky`). 높이 64px, 모바일 56px.
- "새 클레임" 버튼은 어디서나 보이지만 페이지의 주요 행동보다 튀지 않게 연한 초록(`btn accent`)으로 한다. 모바일에서는 하단 탭의 "새 신청"이 대신한다.
- 페이지가 바뀌면 맨 위에서 시작한다. 클레임 상세 안에서 탭만 바꿀 때는 스크롤 위치를 지킨다.

### 화면 구성

**홈 (현황판)** — 로그인하자마자 "얼마가 남았고, 무엇부터 할지"를 안다.
1. 인사: "안녕하세요, ○○님" + 한 문장.
2. 요약 카드 4개: **아직 돌려받지 못한 금액**(초록으로 채운 큰 카드, 통화별 한 줄씩) · 진행 중 건수 · 답변 대기 건수 · 이번 달 회수 금액. 못 받은 금액은 진행 중인 **반품·환불** 건만 센다(교환·AS는 돈이 아니라 물건·수리를 받는다).
3. 지금 해야 할 일: 바로 할 수 있는 일부터 최대 3건(`selectTodo`). 줄마다 상품명·판매처, 다음 할 일, 상태 배지, 남은 금액·회수율, 그 일을 시작하는 버튼.
4. 진행 중인 클레임: 클레임 카드 최대 4장 + "전체 보기".
5. 최근 활동(오른쪽 열, 데스크톱에서 화면에 붙어 따라옴): 여러 클레임의 기록을 시간순으로.
- 클레임이 하나도 없으면 도리 + "아직 등록한 클레임이 없어요" + [첫 클레임 등록하기] + 진행 순서 5단계 안내만 보여 준다.

**클레임 목록** — 검색, 상태 칩(전체·진행 중·분쟁·종료·포기, 건수 표시), 판매처·통화 선택, 정렬(최근 수정 순·미회수 금액 순·진행 단계 순). 미회수 금액 순은 통화가 다르면 비교할 수 없으므로 **통화별로 묶은 뒤** 금액 순으로 놓고, 그렇다고 결과 줄에 적는다. 카드는 데스크톱 3열, 모바일 1열.

**클레임 상세 (실행판)**
- 위: 왼쪽에 판매처·요청 종류, 상품명 + 상태 배지, 주문번호·주문일·마지막 저장. 오른쪽에 **금액 카드**(못 받은 금액 크게 → 청구액·합의액·실제 회수액 → 회수 막대).
- 그 아래 전체 폭의 6단계 진행 카드.
- 데스크톱은 2열: 왼쪽 탭(개요·증빙·문의·답변·회수 기록·활동 내역, 기록 수 표시), 오른쪽 위에서부터 **다음 할 일 카드** → 최근 활동 5건 → 접힌 "사건 관리"(상태 직접 바꾸기, 휴지통으로 이동).
- 모바일·태블릿은 1열: 금액 카드 → 단계 → 다음 할 일 → 탭(칩 모양 버튼) → 사건 관리 → 최근 활동.

**새 클레임 (단계형 신청)** — 다이얼로그 하나에 5단계: ① 기본 정보(판매처·주문번호·주문일·상품명·처리 방식) ② 주문·금액(통화·품목·청구액·합의액) ③ 문제 내용(한국어 설명·영문 설명·판매처 기한) ④ 증빙 ⑤ 확인. 데스크톱은 가운데 720px, 모바일은 화면 전체. 자세한 동작은 7장 "단계 진행"과 9장.

**문의 준비** — 문의 탭은 "받는 곳" 띠 → 초안 도구(AI로 초안·기본 틀·직접 작성) → 메시지 카드(상태 배지, 제목, 본문, 복사·수정·보냈어요). 편집 다이얼로그는 980px로 넓게, 왼쪽에 받는 곳·AI 요약·**보내기 전에 채울 항목**·제목·본문, 오른쪽에 사건 요약·증빙 목록·최근 답변을 둔다. 모바일은 화면 전체에 위아래로.

**설정 (개인 데이터 관리 센터)** — 한 열 카드: 계정 정보 → 이메일 인증 → AI 기능 → 내 데이터 내보내기 → (간격을 두고 빨간 테두리) 회원 탈퇴.

**휴지통** — 지운 클레임 카드(삭제일, 복원 버튼)와 "저절로 지워지지 않고 탈퇴 때만 영구 삭제된다"는 안내.

**로그인·가입** — 가운데 카드. 아래에 약속 세 줄: 내 기록은 본인만 본다 · AI는 동의한 경우에만 · 판매처에 대신 연락하거나 돈을 받지 않는다.

### 무엇을 가운데에 두나

| 요소 | 정렬 |
|---|---|
| 로그인·가입 카드 | 화면 **정중앙**(가로·세로). 최대 폭 420px. 도리(120px)가 카드 위쪽 가장자리 **가운데**에 서 있다 |
| 빈 상태, 오류 상태 | 패널 안에서 **정중앙**. 문장은 가운데 정렬, 최대 폭 36ch. 다음 행동 버튼 1개 |
| 회수 완료 축하 | 다이얼로그 안 **정중앙**: 도리(180px) → 제목 → 금액 → 안내 → 버튼 |
| 진행 단계 | 클레임 제목 아래 카드에 **가로 전체 폭**으로 6칸을 고르게 나눈다 |
| 도리 준비 화면 | 다이얼로그 안에서 **정중앙** |
| 다이얼로그 | 데스크톱·태블릿은 화면 **정중앙**. 모바일은 **하단 시트**(폭 100%, 아래에 붙음). 새 클레임과 문의 편집은 모바일에서 **화면 전체** |
| 다음 할 일 카드 | 데스크톱은 상세 오른쪽 열 맨 위, 모바일은 단계 카드 바로 아래 |
| 토스트 | **하단 가운데**. 모바일은 하단 탭 바 위 |
| 목록, 표, 폼, 상세 내용 | **왼쪽 정렬.** 읽는 흐름을 지키기 위해 가운데 정렬하지 않는다 |
| 금액 숫자 열 | 오른쪽 정렬, `tabular-nums` |
| 페이지 제목 줄 | 제목은 왼쪽, 주요 버튼은 오른쪽. 모바일에서는 제목 아래 전체 폭으로 내린다 |

## 3. 간격 (4px 격자)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--space-1` | 4px | 아이콘과 글자 사이 |
| `--space-2` | 8px | 관련 요소 사이(버튼 묶음, 라벨↔입력) |
| `--space-3` | 12px | 작은 컴포넌트 안쪽 여백 |
| `--space-4` | 16px | 카드 안쪽 여백(모바일), 폼 필드 사이 |
| `--space-5` | 20px | 카드 안쪽 여백(데스크톱) |
| `--space-6` | 24px | 묶음과 묶음 사이 |
| `--space-8` | 32px | 섹션 사이 |
| `--space-12` | 48px | 페이지 위아래 |

규칙: 안쪽 여백은 바깥 간격보다 작아야 한다. 그래야 묶음이 묶음으로 보인다.

## 4. 모서리 (너무 각지지도, 너무 둥글지도 않게)

기준은 **요소 높이의 약 22%**다. 44px 버튼은 10px, 큰 면은 14–20px. 완전히 둥근 알약 모양 버튼은 쓰지 않는다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--radius-sm` | 6px | 상태 배지, 체크박스, 코드 조각 |
| `--radius-md` | 10px | 버튼, 입력칸, 선택칸, 토스트, 안내 상자 |
| `--radius-lg` | 14px | 카드, 패널, 파일·기록 카드, 표 묶음 |
| `--radius-xl` | 20px | 다이얼로그, 로그인 카드, 모바일 하단 시트 위쪽 두 모서리 |
| `--radius-full` | 999px | 원형 요소(아이콘 배경)에만 |

**겹친 모서리 규칙**: 안쪽 모서리 = 바깥 모서리 − 안쪽 여백. 예를 들어 패널(14px) 안에 4px 띄운 강조 상자는 10px.

## 5. 글자

- **글꼴**: Pretendard 1.3.9 가변 글꼴 한 파일(`assets/fonts/PretendardVariable-1.3.9.woff2`, 2MB, SIL OFL 1.1)을 **함께 배포**한다. 그래서 어떤 기기에서도 같은 한글로 보인다.
  - 미리 불러오기(preload)를 쓰고, 글꼴이 오기 전에는 시스템 글꼴로 먼저 보여 준다(`font-display: swap`).
  - 서버는 이 파일만 1년 동안 캐시하게 한다. 파일 이름에 버전이 있으니, 글꼴을 바꿀 때는 새 이름으로 넣는다.
  - 대체 순서: Apple SD Gothic Neo → Malgun Gothic → 시스템 산세리프. Inter·Arial을 기본값으로 쓰지 않는다.
- **크기**(약 1.2배 비율): 12 / 13 / 14 / **15(본문)** / 17 / 20 / 24 / 30px.
- **굵기**: 400 본문, 600 강조·라벨, 700 제목.
- **줄 간격**: 본문 1.6, 제목 1.3.
- **자간**: 제목 −0.02em. 제목에는 `text-wrap: balance`를 준다.
- **금액·수량**: `font-variant-numeric: tabular-nums`.
- **문구**:
  - 로딩·진행 중 표시는 "…"로 끝낸다(예: "저장 중…").
  - 오류 메시지는 무슨 일인지와 어떻게 고치는지를 함께 쓴다.
  - 버튼은 결과를 말한다("저장", "기록", "복원").

## 6. 색

- 바탕과 회색은 **초록빛이 도는 중립색**이다. 순수 검정·순수 회색은 쓰지 않는다.
- 주요 색 `--green` #246a61 하나로 행동을 표시한다.
- AI가 만든 내용에만 보라빛 `--ai-*`를 쓴다.
- 경고는 `--warning-*`, 위험은 `--danger`.
- 상태 배지와 태그는 `--tag-*` 짝(연한 바탕 + 진한 글자)을 쓴다: 회수(초록), 답변 대기·환불 통지(파랑), 검토(보라), 분쟁·포기(주황), 종료(회색).
- 초록으로 채운 면(홈의 못 받은 금액 카드, 선택된 칩) 위의 보조 글자는 `--on-green-muted`다.
- 본문 대비 4.5:1 이상. 색이 들어간 바탕 위에 회색 글자를 쓰지 않는다.
- 그라데이션은 쓰지 않는다. 그림자는 초록빛 섞인 옅은 그림자 두 단계(`--shadow-sm`, `--shadow-lg`)만 쓴다.

## 7. 컴포넌트

| 컴포넌트 | 크기·모양 | 상태 |

## 8. 모션: 언제, 얼마나

**토큰**

| 토큰 | 값 |
|---|---|
| `--dur-instant` | 100ms |
| `--dur-fast` | 160ms |
| `--dur-base` | 220ms |
| `--dur-slow` | 320ms |
| `--ease-out` (들어올 때) | `cubic-bezier(.22,.61,.36,1)` |
| `--ease-in` (나갈 때) | `cubic-bezier(.4,0,1,1)` |

- 튕기는(bounce·elastic) 곡선은 쓰지 않는다.
- 움직임은 `transform`과 `opacity`만 쓴다. 색 변화는 마우스 오버에만 쓴다.
- `transition: all`은 쓰지 않는다.
- 나갈 때는 들어올 때의 약 70% 시간이다.

| 언제 | 무엇이 | 시간·곡선 |
|---|---|---|
| 버튼·링크에 마우스를 올릴 때 | 바탕·테두리 색 | 160ms ease-out |
| 목록 줄에 마우스를 올릴 때 | 바탕 색 | 100ms |
| 버튼을 누를 때 | `scale(.98)` | 100ms |
| 다이얼로그가 열릴 때 | 투명→불투명 + 아래 8px에서 제자리 + `scale(.98→1)`, 뒤 배경도 옅게 나타남 | 220ms ease-out |
| 다이얼로그가 닫힐 때 | 반대로 | 150ms ease-in |
| 모바일 하단 시트가 열릴 때 | 화면 아래에서 위로(`translateY(100%→0)`) | 320ms ease-out (닫힘 200ms) |
| 토스트가 나타날 때 | 아래 12px에서 올라오며 나타남 | 220ms ease-out (사라짐 150ms) |
| 페이지·탭을 바꿀 때 | 새 내용이 투명→불투명(미끄러짐 없음) | 160ms ease-out, 경로가 바뀔 때만 |
| 새 클레임의 단계를 바꿀 때 | 새 단계가 투명→불투명 | 160ms ease-out |
| 모바일 "새 신청" 원 버튼을 누를 때 | `scale(.96)` | 100ms |
| 목록을 처음 불러올 때 | 스켈레톤 깜빡임 | 1s linear 반복. 데이터가 오면 바로 교체, 줄마다 순서대로 나타나기 없음 |
| 도리가 문의를 준비할 때 | 서류 정리 반복 동작 | 1.6s 반복. 최소 2.5초 보여 줌. 취소하면 바로 멈춤 |
| 로그인·가입 화면이 열릴 때 | 도리가 날개를 흔든다 | 1.2s ease-in-out × 2회, 화면이 바뀔 때만 |
| 실제 회수를 처음 다 받았을 때 | 축하 다이얼로그: 도리가 두 번 뛰고 색종이가 한 번 터진다 | 뛰기 600ms × 2, 색종이 1.4s 한 번. 앱 전체에서 **유일한 축하 장면**이다 |
| 검색어를 칠 때, 저장된 값이 바뀔 때 | **움직이지 않음** | – |

**모션 줄이기**(`prefers-reduced-motion: reduce`): 위치·크기 변화는 모두 없앤다. 나타남·사라짐은 즉시 바뀐다. 도리는 멈춘 자세로 보여 준다.

## 9. 상태와 문구

- **불러오는 중**: 스켈레톤. 글자로만 "불러오는 중…"을 쓰는 것은 처음 부팅할 때뿐이다.
- **비어 있음**: 왜 비었는지와 다음 행동을 버튼 1개로 보여 준다.
- **입력 오류**: 틀린 입력칸 **바로 아래**에 빨간 문장을 띄우고, 칸 테두리를 빨갛게 하고, 첫 번째 틀린 칸으로 커서를 옮긴다.
  - 브라우저 기본 말풍선은 쓰지 않는다. 같은 자리에 한국어 문장을 띄운다.
  - 서버가 거절하면 응답의 `field`(예: `claimedAmount`, `items.0.unitPrice`) 자리에 띄운다. 칸을 특정할 수 없는 오류만 폼 맨 아래에 둔다.
  - 그 칸을 다시 고치기 시작하면 문장이 사라진다.
- **단계형 폼(새 클레임)**:
  - [다음]은 지금 단계의 칸만 검사한다. 틀린 칸이 있으면 단계가 넘어가지 않는다.
  - 마지막 단계 전에는 입력칸에서 Enter가 [다음]과 같다. 여러 줄 입력칸의 Enter는 줄 바꿈이다.
  - 등록 때 서버가 거절한 칸이 다른 단계에 있으면 그 단계로 돌아가 칸 아래에 문장을 띄운다. 접힌 칸(판매처 기한)은 펼친다.
  - 품목의 "문제 수량 × 단가" 합계를 보여 주고 [청구액으로 쓰기]를 제안한다. 같으면 "청구액과 같아요"라고만 쓴다.
  - 4단계에서 고른 증빙은 클레임이 만들어진 뒤에 하나씩 올린다. 형식·크기가 틀린 파일은 고르는 순간 알린다. 올리지 못한 파일이 있으면 클레임은 그대로 두고 이름을 알려 증빙 탭으로 보낸다.
  - "주문서로 자동 채우기"로 읽은 파일은 4단계 증빙 목록에도 들어간다.
- **AI가 채운 칸**: 보라 테두리와 연한 보라 면. 사용자가 그 칸을 고치면 표시가 사라진다. 채운 항목을 AI 안내 상자에 적는다.
- **저장 전 미리보기(회수 기록)**: 금액이나 수량을 치는 대로 "실제 회수액 €0.00 → €20.00, 회수율 0% → 50%"를 보여 준다. 목표를 넘으면 노란 경고, 딱 맞으면 "합의액을 모두 받게 돼요".
- **답변 기록**: 답변 종류를 고르면 저장하면 무엇이 바뀌는지 한 줄로 알려 준다(예: "분쟁으로 바뀌어요").
- **그 밖의 오류**: 토스트로 띄우고, 무엇을 하면 되는지 쓴다.
- **AI 기다림**: 실제 응답은 7~19초가 걸린다. 누른 버튼 **바로 아래**에 보라색 진행 줄을 띄운다.
  - 순서: 회전 표시 → "AI가 ○○하는 중…" → "보통 10초 안팎 걸려요" → 지난 초 → [취소]
  - 20초가 넘으면 안내를 "평소보다 오래 걸리고 있어요. 계속 기다리거나 취소할 수 있어요"로 바꾼다.
  - 취소하면 늦게 온 결과는 버리고 "AI 작업을 취소했어요" 토스트를 띄운다.
  - 문의 초안은 도리 화면이 이 역할을 한다.
  - AI 작업은 한 번에 하나만 돌린다.
- **작성 중 닫기**: 다이얼로그 폼에 입력한 내용이 있을 때 닫기·Esc를 누르면 위에 확인 창을 띄운다.
  - 확인 창 버튼은 [계속 작성] [버리고 닫기]다.
  - AI가 만든 초안이나 AI가 읽은 값으로 채운 폼은 처음부터 "입력 있음"으로 친다.
  - 새로고침하거나 탭을 닫을 때는 브라우저 확인을 띄운다.
- **토스트 위치**: 다이얼로그가 열려 있으면 다이얼로그 안 **위쪽 가운데**에 띄운다. 아래 버튼을 가리지 않고, 모달 뒤에 숨지도 않는다.
- **오프라인**: 맨 위 띠. 연결이 돌아오면 토스트로 알린다.
- **이메일 미인증**: 맨 위 초록 띠(`--green-soft`). 문장은 왼쪽, '인증 메일 다시 받기' 테두리 버튼은 오른쪽(본문 열에 맞춤). 모바일은 버튼을 문장 아래 전체 폭으로 내린다. 인증하면 사라진다. 주요 버튼이 아니므로 채운 버튼을 쓰지 않는다.
- **다음 할 일 순서**(`selectNextAction`): 휴지통 → 종료 → 포기 → 모두 받음(종료하기) → 분쟁 → 증빙 없음 → 초안 없음 → 다시 써야 할 초안 → 보내지 않은 초안 → 답변 대기 → 추가 증빙 요청 → 합의액 없음(환불) → 회수 기록. 홈의 "지금 해야 할 일"은 바로 할 수 있는 일(종료·분쟁·회수·합의액·증빙 보강·보내기·초안·증빙)을 먼저, 기다리는 일(답변 대기)을 나중에 놓는다.
- **메일 링크로 여는 화면**(인증·재설정): 인증은 페이지가 아니라 동작이라 결과를 토스트로 알리고 대시보드나 로그인으로 보낸다. 재설정은 로그인 카드와 같은 가운데 카드다. 비밀번호 재설정 요청 뒤에는 계정 유무와 상관없이 같은 '메일함을 확인하세요' 화면을 보여 준다.
- **되돌릴 수 없는 행동**: 확인 다이얼로그를 띄운다(삭제, 탈퇴). 탈퇴는 비밀번호까지 받는다.

## 10. 접근성 체크리스트

- [ ] 토스트와 검증 메시지는 `aria-live`로 알린다.
- [ ] 본문 바로가기 링크가 있고, 제목 순서가 맞다.
- [ ] 다이얼로그 안에서 Tab이 순환하고, Esc로 닫힌다.
- [ ] 확대를 막지 않는다. 모바일 입력칸은 16px다.
- [ ] 모션 줄이기 설정을 지킨다.
- [ ] 노치·홈 바 안전 영역(`env(safe-area-inset-*)`)을 둔다.
